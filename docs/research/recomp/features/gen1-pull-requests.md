## #7 Japanese disc (SLPS-01855): its own program, switched to by disc

Branch `jp-disc` · merged · opened 2026-11-24

Step 0.2: the Japanese Master of Arena disc 1 (SLPS-01855) plays too.

**What changes**
- The Japanese disc's game code is different from the US disc's, so it gets its own recompile: `game-jp.toml`, `seeds/ghidra_funcs_jp.txt` and `generated-jp/` (1,083 functions; every file compiles). It was made with the same procedure that rebuilds the US code byte for byte.
- CMake option `ACG_REGION` (`US` default, `JP`) chooses which program a build makes.
- Windows release: the Japanese program sits in `RecompData/Japan/` with its own `game.toml`. `RecompData/regional-launch.toml` tells the framework's built-in regional switch which disc belongs to which program. When the disc found or picked is the other version's, the program closes and starts the other one, passing the memory card folder along. The last disc used is remembered.
- Launcher: the disc finder takes either disc (its own first). In the Japanese program the menu reads MASTER OF ARENA JAPAN, and START GAME offers only LAUNCH GAME (normal boot). LOAD GAME and NEW GAME need the US addresses found on the Japanese disc first.
- Updater: treats `RecompData/Japan/` as part of the game and keeps the player's files there.
- CI: the Windows runner builds the Japanese program a second time (`build-ci-jp`). The zip check makes sure both configs, the list and both exes are there.

**Limits**
- Windows only for the Japanese program (the framework's switch is Windows-only).
- Discs are recognized by the exact SHA-256 and size of the `.bin`. Only these dumps work while the list ships: your US dump (same as the old fork's) and your Japanese D2D dump. A `.chd` won't match.
- Each program has its own settings and mods; memory cards are shared.

**First build with this:** the updater should install it, since the folder layout is unchanged. It adds `RecompData/Japan/`.

Details: `regional/README.md`.

## #9 Launcher: restart the game by itself after an update

Branch `feat/restart-after-update` · merged · opened 2026-11-24

After an update installs, the UPDATES page shows **UPDATED TO … RESTARTING** for two seconds, then the game restarts by itself.

How: the game starts the starter (`Armored Core Gen 1.exe`) with `--after-update <process id>` and closes through the launcher's normal quit. The starter waits for that old copy to close (up to 30 s) so the two never run at once, then starts the new game as a normal start does: same `Memory Card/` folder, last disc (US or Japanese, through the regional switch). If the starter is missing or won't start, the old "close the game and start it again" message stays.

Considered: the framework's own relaunch (`LNG_ACTION_RELAUNCH`) is for restarting after it rebuilds itself; it drops our `--memcard-dir`, skips the starter and starts the new copy while the old one is still open, so it isn't used.

Note: the restart is done by the copy that's running, so it works for updates made **from** this version on. 0.0.5.1 → 0.0.6 still needs one manual restart.

Checked in the sandbox: launcher (US and JP) and updater syntax-check; starter and the Windows restart code checked with stand-in Windows headers.
